# Implementation Plan: Download Release Date

**Branch**: `003-download-release-date` | **Date**: 2026-08-06 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/003-download-release-date/spec.md`

## Summary

Add the release date of the currently offered installer to the Download section, appended to the existing version/platform line in the installer card ("Version 0.1.1 for Windows 11, x64 · released August 6, 2026"). The date is stored once in `src/_data/site.json` (ISO 8601, key `releaseDate`) next to the existing `version` key, rendered as a human-readable English date via a new Nunjucks filter, and validated at build time — a missing, empty, or invalid date fails the Eleventy build with a clear error (FR-006).

## Technical Context

**Language/Version**: JavaScript (Node.js 20 locally; CommonJS Eleventy config)

**Primary Dependencies**: Eleventy (@11ty/eleventy ^3.0.0), Nunjucks templates; Wrangler ^4.0.0 for deploy (requires Node 22 — build/dev work on Node 20)

**Storage**: `src/_data/site.json` — Eleventy global data file already holding `version` and all site-wide release facts

**Testing**: No test framework in repo; validation via `npm run build` (must fail on bad config), inspection of generated `public/index.html`, and `npm run dev` visual check per quickstart.md

**Target Platform**: Static site (Eleventy → committed `public/`), hosted on Cloudflare Workers

**Project Type**: Static marketing/product website (single page, Nunjucks section includes)

**Performance Goals**: N/A — one additional data value and one filter call at build time; zero runtime cost

**Constraints**: Date must render in English matching site language; layout intact at both desktop and mobile widths (site breakpoint 860 px); build must fail loudly on missing/invalid date

**Scale/Scope**: 1 data file (+1 key), 1 config file (+1 filter with validation), 1 template line changed; no CSS changes expected
