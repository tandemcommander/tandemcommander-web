# Tasks: Installation Through winget on the Website

**Input**: Design documents from `/specs/010-winget-install/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/download-ui.md](contracts/download-ui.md), [quickstart.md](quickstart.md)

**Tests**: One source-level test suite (`tests/site.winget.test.js`) is part of the plan (research
R2, R7) and is built up across the phases. No other automated tests are requested; the visible
result is verified by the quickstart scenarios.

**Organization**: Tasks are grouped by user story. The stories share few files, so most work is
sequential; `[P]` marks the tasks that touch a file no other open task touches.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1-US4)
- Paths are relative to the repository root `E:\Projects\tandemcommander-web`

## Standing rules for every task

- Work on branch `010-winget-install`. Do not commit to `devel` or `main`, merge or deploy.
- Never edit files under `public/` by hand; they are regenerated by `npm run build`.
- Do not touch `content/releases/`, `src/pad.njk`, `src/_data/pad.js`, `src/js/main.js`, the hero
  or the header (FR-010, spec Assumptions, research R5).
- JSON files: 2-space indentation, UTF-8, trailing newline, key order preserved.
- No em or en dashes in texts; use a plain hyphen, as the existing catalogs do.

## Implementation Strategy

### MVP (User Story 1)

T001 → T002-T003 → T004-T008. The site then offers the working install command in both languages.
This could be published alone, with one known blemish: the hint still names the old short update
command and card 06 still says "on its way".

### Incremental delivery

1. US1 - the option is visible and works.
2. US2 - the hint matches the install command; the option is complete.
3. US3 - the contradiction on card 06 is gone.
4. US4 - the switch is proven in both directions and documented.
5. Polish - full checks, diff review, handover.

Given the size of the feature (24 tasks, most a single edit), doing all phases in one pass and
publishing once is the expected path.
