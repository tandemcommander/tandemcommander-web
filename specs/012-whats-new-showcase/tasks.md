# Tasks: What's New Showcase (replacing the "Old habits" section)

**Input**: Design documents from `specs/012-whats-new-showcase/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/showcase-ui.md](contracts/showcase-ui.md),
[contracts/content-rules.md](contracts/content-rules.md), [quickstart.md](quickstart.md)

**Tests**: Included - the plan names the suites (`content.records`, `content.gallery`, new
`content.showcase`, `release.status`, `site.winget`); all are pure `node:test` tests over
fixtures, no build, no network.

**Organization**: Grouped by user story. US1 (showcase) and US2 (removal) both touch
`whats-new.njk`, the two `index.njk` files and the i18n catalogs, so where they meet the tasks are
sequential (no [P]).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 = visual showcase (P1), US2 = remove the stale section (P2), US3 = release cycle
  (P3)
- Paths are relative to the repository root `E:\Projects\tandemcommander-web`

## Standing rules for every task

- Work on branch `012-whats-new-showcase`. Never commit to `devel` or `main`, never merge or deploy;
  commit only after the author approves.
- Never edit `public/` by hand; it is regenerated by `npm run build`.
- No new npm dependency. `lib/content.js` and `src/_data/*.js` stay CommonJS; `tools/` and `src/js/`
  stay ES modules. Pure logic goes into `lib/content.js` / `tools/release/status.mjs`;
  `tools/release/release.mjs` runs on import and must never be imported by tests.
- Every visible string lives in both `src/_data/i18n/en.json` and `cs.json` with identical keys
  (the build checks parity). Czech texts use „…“ quotes and a spaced hyphen " - " as the catalogs do.
- No scrollbar inside any box, no fixed heights for text; mobile breakpoint is `max-width: 859.98px`.
- Tests: `node:test` + `node:assert/strict`, a header comment naming this spec, style of the
  neighbouring test file. JSON 2-space, UTF-8, trailing newline.
- Match the surrounding code's comment density and naming.
