# Tasks: One-Command Website Update for a New Version (`/tandem-new-version`)

**Input**: Design documents from `specs/011-tandem-new-version/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/release-cli.md](contracts/release-cli.md),
[contracts/skill.md](contracts/skill.md), [quickstart.md](quickstart.md)

**Tests**: Included - the plan names four new `node:test` suites; all are pure-function tests over
fixtures, no network, no Sandbox, no build.

**Organization**: Tasks are grouped by user story. The skill file
`.claude/skills/tandem-new-version/SKILL.md` grows story by story (US1 creates it; US2-US5 add
their sections), so its tasks are sequential.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1-US5)
- Paths are relative to the repository root `E:\Projects\tandemcommander-web`

## Standing rules for every task

- Work on branch `011-tandem-new-version`. Do not commit to `devel` or `main`, merge or deploy.
- Never edit files under `public/` by hand; they are regenerated by `npm run build`.
- No change under `content/`, `src/` or `public/` (temporary edits in a validation task are
  restored); this feature changes the release *tooling*, not the website.
- No new npm dependency. Tools are ES modules (`.mjs`), `lib/content.js` stays CommonJS.
- Pure logic goes into importable modules (`changelog.mjs`, `status.mjs`, `scan.mjs`,
  `verify.mjs`, `lib/content.js`); only `release.mjs` touches the network, git or writes files.
  `release.mjs` runs a command on import and must never be imported by tests.
- Tests: `node:test` + `node:assert/strict`, a one-line header comment naming this spec, style of
  `tests/release.changelog.test.js`. No test may use the network.
- Match the surrounding code's comment density and naming; JSON 2-space, UTF-8, trailing newline.
- Never read `../tandemcommander` (FR-002a).

## Implementation Strategy

### MVP (User Story 1)

T001-T002 → T003-T010 → T011-T018. The next release can then be done with `/tandem-new-version`:
GitHub-only facts, digest review, branch, record, verified build, handover. Without US2-US5 the
author would still scan texts, run the capture and commit by hand.

### Incremental delivery

1. US1 - one command, verified output.
2. US2 - stale text found and corrected in the same review.
3. US3 - the picture decision at the start, capture and visual check.
4. US4 - the approved commit.
5. US5 - resume.
6. Polish - documentation, full checks, rehearsal, scope.

All phases are expected in one pass; the feature is merged once.
