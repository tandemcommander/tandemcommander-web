# Data Model: Website Release for Tandem Commander 0.1.9

No entity is introduced. This release changes instances of the entities defined by feature 007
(`specs/007-release-news-gallery/data-model.md`). Listed here: which instances change, to what,
and the rules that decide whether the result is valid.

## 1. Release facts - `src/_data/site.json`

| Field | Before | After | State |
|-------|--------|-------|-------|
| `version` | 0.1.8 | 0.1.9 | already applied |
| `releaseDate` | 2026-09-20 | 2026-10-07 | already applied |
| `installerSizeBytes` | 8247136 | 8013936 | already applied |

Rule: written only by `npm run release:apply`; must equal the published release
([research.md](research.md) R1). Every version-dependent value on the site derives from here.

## 2. Release record - `content/releases/0.1.9.json`

| Field | Value | Written by |
|-------|-------|------------|
| `version` | `"0.1.9"` | release script (kept) |
| `date` | `"2026-10-07"` | release script (kept) |
| `build` | `193` | release script (kept) |
| `kind` | `"feature"` | approved digest |
| `summary.en`, `summary.cs` | see contract | approved digest |
| `highlights[0..5]` | see contract | approved digest |

Each highlight: `id` (kebab-case, unique in the record), `title.{en,cs}`, `text.{en,cs}`; no
`scene`. Order: `update-check`, `rar-built-in`, `archive-edits-kept`, `any-script-text`,
`pictview-save-as`, `no-password-in-history`.

Validation (build gates and `tests/content.records.test.js`): every site language present ·
summary ≤ 200, title ≤ 40, text ≤ 220 characters · plain text, backticks only as inline markers ·
no `<`, `>`, tab, line break, em or en dash · 0 to 6 highlights. File format: 2-space JSON, UTF-8,
trailing newline.

State transition of the record:

```text
skeleton (empty summary, no highlights)   <- now; build rejects it
        │  author approves the digest - done 2026-10-07
        ▼
recorded (content = contracts/digest-0.1.9.md)
        │  npm run release:check passes
        ▼
checked  ->  committed, merged, deployed by the author
```

Content: [contracts/digest-0.1.9.md](contracts/digest-0.1.9.md).

## 3. Capture records - `content/gallery/captures.json`

Written only by `npm run shots`. Five entries change:

| Key | `appVersion` / `appBuild` | `capturedAt` |
|-----|---------------------------|--------------|
| `main-window/light` | 0.1.8 / 192 → 0.1.9 / 193 | → 2026-10-07 (date of the run) |
| `dark-theme/dark` | same | same |
| `panel-tabs/light` | same | same |
| `unicode-long-paths/light` | same | same |
| `thumbnails/light` | same | same |

`bytes` change with the new images; `width`, `height`, `files`, `environment` (`sandbox`), `dpi`
(96) must stay as they are. Unchanged entries: `code-viewer/light`, `markdown-viewer/light`,
`command-shell/light` (remain 0.1.8).

Staleness rule (`lib/content.js`, `staleReport`): a capture older than the current release is
*must re-capture* when its scene has `showsVersion: true` or a highlight of the current release
references it; otherwise *older, review*. Target state: *must* empty, *review* = the three
unchanged entries, *current* = the five re-captured ones.

## 4. Images

| File | Source scene | Rule |
|------|--------------|------|
| `src/assets/gallery/<scene>-<theme>.webp` and `-640.webp` for the five scenes | the scene | ≤ 300 KB each; title bar reads 0.1.9 |
| `src/assets/screenshot-light.png` | `main-window` | permanent address, referenced by `/pad.xml` |
| `src/assets/screenshot-dark.png` | `dark-theme` | same pixel size as the light one |

A failed scene keeps its previous image and leaves the release unfinished (spec edge case).

## 5. Generated site - `public/`

Wholly derived; regenerated by the build. Must exist afterwards and reflect 0.1.9:
`index.html`, `cs/index.html`, `releases/index.html`, `cs/releases/index.html`, `pad.xml`,
`sitemap.xml`, plus the copied images. Never edited by hand.

## Unchanged by decision

`content/gallery/scenes.json` (FR-017) · `src/_data/i18n/en.json`, `cs.json` and `src/pad.njk`
(FR-018) · all templates, styles, scripts, tools and tests.
