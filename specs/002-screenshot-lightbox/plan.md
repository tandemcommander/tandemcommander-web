# Implementation Plan: Screenshot Lightbox

**Branch**: `002-screenshot-lightbox` | **Date**: 2026-08-05 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-screenshot-lightbox/spec.md`

## Summary

Clicking either application screenshot in the `#screens` section opens it in a near-fullscreen lightbox over a dimmed backdrop, closable via a cross in the top-right corner, Escape, or a backdrop click. The image animates smoothly (no bounce) from its place in the grid to the enlarged position and back. Implementation is a small vanilla-JS + CSS addition to the existing Eleventy site: a native `<dialog>` element for the overlay (free Escape handling, focus containment, top-layer rendering) combined with a FLIP-style transform animation between the thumbnail rect and the centered enlarged rect. No new dependencies.

## Technical Context

**Language/Version**: HTML (Nunjucks templates), CSS, vanilla JavaScript in the existing ES5-flavoured IIFE style of `src/js/main.js`; built with Node 20 / Eleventy 3

**Primary Dependencies**: none added — `@11ty/eleventy` (build only); no runtime libraries, no bundler

**Storage**: N/A (purely presentational; no data persisted)

**Testing**: manual browser validation per `quickstart.md` (desktop + mobile emulation, reduced-motion emulation) plus `npm run check` (build + wrangler dry-run)

**Target Platform**: evergreen desktop and mobile browsers (Chrome, Edge, Firefox, Safari); site breakpoint at 860 px

**Project Type**: static marketing website (Eleventy → committed `public/`, served by Cloudflare Workers)

**Performance Goals**: open/close transition each under 500 ms (SC-002), animating only `transform` and `opacity` so it holds 60 fps; JS addition ≤ ~2 KB unminified

**Constraints**: no new runtime dependencies; must coexist with the global transition rule `body * { transition: … }` (src/css/main.css:103) — the lightbox animation must set its own explicit `transition` so the global one cannot interfere; must honor `prefers-reduced-motion`; page behind overlay must not scroll; keyboard and touch operable

**Scale/Scope**: one page, one section (`#screens`), currently 2 images (light/dark theme screenshots — placeholder assets, finals drop in later with no change to this feature); single-image view only (no in-lightbox navigation, per clarification)
