## Phase 3: User Story 1 - Enlarge a screenshot on click (Priority: P1) 🎯 MVP

**Goal**: Click/tap a screenshot → near-fullscreen view over a dimmed backdrop with a top-right cross that closes it; page scroll locked while open, restored on close.

**Independent Test**: Quickstart scenarios 1 (open & close via cross), 5 (scroll lock), 8 (rapid clicks) pass on desktop and <860 px viewports — with no animation present yet.

### Implementation for User Story 1

- [X] T004 [P] [US1] Add the "Lightbox" CSS block to `src/css/main.css`: `.shot-zoom` button reset (display:block, no border/padding, `cursor: zoom-in`); `.lightbox` viewport-filling layout centering `.lightbox-img` at max ~90vw/90vh with preserved aspect ratio; `.lightbox::backdrop` dimmed (~rgba(0,0,0,.75)); `.lightbox-close` cross anchored top-right with ≥40×40 px target; `html.lightbox-open { overflow: hidden }`; `@media (max-width: 859.98px)` adjustments keeping the cross reachable
- [X] T005 [P] [US1] Add the "Screenshot lightbox" IIFE section to `src/js/main.js` (existing ES5 style): state per data-model.md (`closed`/`opening`/`open`/`closing`, singleton, re-entrancy guard ignoring activation when not `closed`); on `.shot-zoom` click copy `src`/`alt` to `.lightbox-img`, call `dialog.showModal()`, add `lightbox-open` class to `<html>`; on `.lightbox-close` click call `dialog.close()` and remove the class (states collapse instantly — animation arrives in US2)
- [ ] T006 [US1] Validate US1 per `specs/002-screenshot-lightbox/quickstart.md` scenarios 1, 5, 8 at desktop width and <860 px emulation; fix findings

## Phase 4: User Story 2 - Playful animated transition (Priority: P2)

**Goal**: The image smoothly zooms from its grid position into the enlarged view and back — brisk tempo, no overshoot/bounce (per clarification) — honoring reduced-motion preferences.

**Independent Test**: Quickstart scenarios 2 (animation quality: grows from grid position, <0.5 s each way, no stutter, no bounce) and 6 (reduced motion) pass.

### Implementation for User Story 2

- [X] T007 [P] [US2] Add animation CSS to the Lightbox block in `src/css/main.css`: explicit `transition` on `.lightbox-img` for `transform`/`opacity` (~300 ms open / ~250 ms close, smooth ease-in-out cubic-bezier, no overshoot) and backdrop fade — explicit so the global `body *` transition rule (main.css:103) cannot interfere (research R7); `@media (prefers-reduced-motion: reduce)` disables the transform transition (short fade or instant)
- [X] T008 [P] [US2] Implement FLIP animation in the lightbox section of `src/js/main.js` (research R1): on open, measure the clicked thumbnail's `getBoundingClientRect()`, apply inverting `translate(...) scale(...)` from the final centered rect, force reflow, transition to `transform: none`; on close, play the inverse back to the (re-measured) thumbnail rect before `dialog.close()`; settle `opening`→`open` and `closing`→`closed` on `transitionend` with a ~450 ms timeout fallback and a `prefers-reduced-motion` matchMedia guard (data-model.md rules)
- [ ] T009 [US2] Validate US2 per `specs/002-screenshot-lightbox/quickstart.md` scenarios 2 and 6 (including DevTools reduced-motion emulation); fix findings

**Checkpoint**: US1 + US2 — the full requested experience (animated playful lightbox).
